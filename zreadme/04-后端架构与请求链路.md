## 一、为什么选 Flask

| 对比项 | Flask | Django |
| --- | --- | --- |
| 定位 | 微框架 | 全家桶 |
| 起步 | 单文件即可运行 | 需要 `startproject` 与固定目录约定 |
| 路由 | 装饰器 / `add_url_rule`，自由 | `urls.py` 集中配置 |
| ORM | 自选（本项目 Flask-SQLAlchemy） | 内置 |
| 目录结构 | 由你设计 | 官方强约定 |

本项目是纯 JSON API：接请求、连库、跨域、接大模型 SDK，四件事 Flask 生态都够用，而且**目录结构可以自己设计**——分层架构不是框架给的，是搭出来的。

Flask 的两个关键特性被大量使用：

- **蓝图**：把一组 URL 打包注册，见 `internal/router/router.py`；
- **应用装配**：`Flask` 子类化 + `config.from_object()` + `init_app()`，见 `internal/server/http.py`。

## 二、分层架构总览

```text
llmops-api/
├── app/http/
│   ├── app.py           # 入口：load_dotenv → Config → Injector → Http → run
│   └── module.py        # 依赖注入绑定表
├── internal/            # 业务层
│   ├── router/          # URL → Handler 方法
│   ├── handler/         # 控制器：收参、调服务、包响应
│   ├── service/         # 业务逻辑 + 数据库读写
│   ├── model/           # ORM 模型
│   ├── schema/          # 请求校验（FlaskForm）
│   ├── exception/       # 自定义异常
│   ├── server/          # Http 引擎（Flask 子类）
│   ├── extension/       # db / migrate 实例
│   └── migration/       # Alembic 目录
├── pkg/
│   ├── response/        # 统一响应 + 业务状态码
│   └── sqlalchemy/      # 带 auto_commit 的 SQLAlchemy 子类
├── config/              # 环境变量 → Python 对象
└── test/                # pytest
```

| 层 | 目录 | 只做一件事 | 不允许 |
| --- | --- | --- | --- |
| 应用层 | `app/` | 组装零件 | 写业务 |
| 业务层 | `internal/` | 路由、校验、业务、模型 | 直接读 env 拼配置 |
| 基础设施 | `pkg/` | 通用工具 | 依赖具体业务 |
| 配置层 | `config/` | 环境变量 → 大写属性 | 写业务判断 |

依赖方向单向：`app → internal → pkg`，`internal → config`。

## 三、启动链路

### 3.1 为什么必须 `python -m app.http.app`

```python
# app/http/app.py 第 68 行
from .module import ExtensionModule
```

`.` 表示相对导入，要求模块知道自己的 `__package__`：

- `python app/http/app.py`：文件被当顶层脚本，`__package__ is None` → `ImportError: attempted relative import with no known parent package`；
- `python -m app.http.app`：按模块路径导入，`__name__ == "__main__"`、`__package__ == "app.http"`，相对导入成立。

```bash
# 必须在项目根目录执行（否则找不到 .env 和 internal 包）
python -m app.http.app
```

### 3.2 九步走

```python
import dotenv
from flask_migrate import Migrate
from injector import Injector

from config import Config
from internal.router import Router
from internal.server import Http
from pkg.sqlalchemy import SQLAlchemy
from .module import ExtensionModule

dotenv.load_dotenv()                     # ① 注入环境变量
conf = Config()                          # ② 读环境变量生成配置对象
injector = Injector([ExtensionModule])   # ③ 只登记绑定规则
app = Http(                              # ④ 组装 Flask 应用
    __name__,
    conf=conf,
    db=injector.get(SQLAlchemy),
    migrate=injector.get(Migrate),
    router=injector.get(Router),
)

if __name__ == "__main__":               # ⑤ 只有直接运行才起服务
    app.run(debug=True)
```

**① `load_dotenv()`**：向上查找 `.env`，解析 `KEY=VALUE` 写入 `os.environ`，已存在的同名变量不覆盖。`import dotenv` 本身不读文件。

**② `Config()`**：`config/config.py` 的所有取值都写在 `__init__` 里：

```python
def _get_env(key: str) -> Any:
    return os.getenv(key, DEFAULT_CONFIG.get(key))
```

如果写成类属性，`import config` 那一刻就求值，早于 `load_dotenv()`，读到的全是 `None`。这就是「先 import 后 load 也没问题」的原因——真正读取发生在实例化时。

**③ `Injector([ExtensionModule])`**：执行 `binder.bind(...)` 登记规则，不立即创建对象（懒加载）。

**④ `Http(...)`**：`injector.get(Router)` 触发递归构造：

```text
Router(app_handler: AppHandler)
  └─ AppHandler(app_service: AppService)
       └─ AppService(db: SQLAlchemy)
            └─ 命中 binder.bind(SQLAlchemy, to=db) → 全局 db
```

`Http.__init__`（`internal/server/http.py`）内部依次：

1. `super().__init__(*args)` 初始化 Flask；
2. `config.from_object(conf)` 搬运**大写开头**属性；
3. `register_error_handler(Exception, self._register_error_handler)`；
4. `db.init_app(self)`、`migrate.init_app(self, db, directory="internal/migration")`；
5. `CORS(self, resources={...})`；
6. `router.register_router(self)`。

**⑤ `app.run(debug=True)`**：只在直接运行时执行；`flask db upgrade` 这类命令只 import 模块，不会启动服务器。

### 3.3 为什么用 injector

手写依赖是 `service = AppService(db=db)` → `handler = AppHandler(app_service=service)` → `router = Router(...)`，对象一多就容易顺序错、传参错。injector 提供：构造函数注入（`@inject` + `@dataclass` + 类型注解）、解耦（Handler 不关心 Service 怎么造）、可测试（bind 假实现）、单例复用（`db`/`migrate` 全局一份）。本项目只用最基础能力：`module.py` 两条绑定 + 自动装配。

## 四、一次请求的完整生命周期

路由定义（`internal/router/router.py` 第 28 行，本地唯一启用）：

```python
bp.add_url_rule("/apps/<uuid:app_id>/debug", methods=["POST"], view_func=self.app_handler.debug)
```

请求 `POST /apps/<uuid>/debug`，body `{"query":"你好"}`：

```text
前端
 │  POST /apps/<uuid>/debug
 ▼
[1] Flask 路由匹配：url_map 命中 "/apps/<uuid:app_id>/debug" + POST
 ▼
[2] uuid 转换器：app_id 必须能被 uuid.UUID() 解析，否则 404（不进视图）
 ▼
[3] 视图函数：注册路由时已绑定 self.app_handler.debug（injector 早已注入）
 ▼
[4] AppHandler.debug(app_id)
 │   4.1 CompletionReq() 自动读 request.get_json()
 │   4.2 validate() 执行 DataRequired / Length(max=2000)
 │       失败 → validate_error_json(req.errors)，直接返回
 ▼
[5] LangChain 链：prompt("{query}") | ChatOpenAI(deepseek-flash) | StrOutputParser()
 │   chain.invoke({"query": req.query.data})，内部 dict → PromptValue → AIMessage → str
 ▼
[6] success_json({"content": content})
 │   {"code":"success","message":"","data":{"content":"..."}}
 ▼
[7] after_request：Flask-CORS 追加响应头
 ▼
[8] Werkzeug 输出 200 + JSON
```

必须强调：

- **`app_id` 只做格式校验**。`debug()` 内部没有拿它查库，任何合法 UUID 都能拿到回答；后续章节才会用它读应用配置与历史。
- UUID 格式错 → 404，**不会进 Handler**。前端报 404 先查 id 格式。
- 未配 `OPENAI_API_KEY` 等异常会走全局异常处理，debug 模式下见 5.7。

## 五、各层职责与代码要点

### 5.1 路由：`internal/router/router.py`

```python
@inject
@dataclass
class Router:
    app_handler: AppHandler

    def register_router(self, app: Flask):
        bp = Blueprint("llmops", __name__, url_prefix="")
        # bp.add_url_rule("/ping", view_func=self.app_handler.ping)
        # bp.add_url_rule("/app/completion", methods=["POST"], view_func=self.app_handler.completion)
        bp.add_url_rule("/apps/<uuid:app_id>/debug", methods=["POST"], view_func=self.app_handler.debug)
        app.register_blueprint(bp)
```

- 蓝图是「一组路由的容器」，便于后续按模块拆 `/apps`、`/datasets`；
- `url_prefix=""`，所以写完整路径；
- `<uuid:app_id>` 是转换器，负责格式校验与类型转换；
- 路由集中注册，一张表看清所有接口。

课程 vs 本地：路径一致，均只启用 `debug`；`/ping`、`/app/completion`、`/app` CRUD 全部注释。**Handler 里方法还在，路由却没开**——迁移中的典型状态，也是旧测试失效的根因。

### 5.2 控制器：`internal/handler/app_handler.py`

```python
@inject
@dataclass
class AppHandler:
    app_service: AppService
```

- `@dataclass` 生成 `__init__`；`@inject` 让容器按注解装配；
- 顺序：`@inject` 必须在 `@dataclass` **上面**，否则 `__init__` 尚未生成。

`debug` 逐行：

| 代码 | 作用 |
| --- | --- |
| `req = CompletionReq()` | 构造时从 `request.get_json()` 绑定 `query` |
| `req.validate()` | 返回 bool；失败时 `req.errors = {"query": ["..."]}` |
| `validate_error_json(req.errors)` | 包装成 `code=validate_error` 的统一响应 |
| `ChatPromptTemplate.from_template("{query}")` | 单变量聊天模板 |
| `ChatOpenAI(model="deepseek-flash")` | 未传 key/base_url，读环境变量 |
| `StrOutputParser()` | 从 `AIMessage` 取 `content` |
| `prompt \| llm \| parser` | LCEL 生成 `RunnableSequence` |
| `chain.invoke({"query": ...})` | 键名必须与模板变量一致，否则 `KeyError` |
| `success_json({...})` | 统一响应结构 |

两点提醒：

1. `app_id` 未参与业务，纯占位。
2. 本地文件顶部只 `import uuid`，签名却写 `app_id: UUID`。本项目使用 **Python 3.14**，注解默认惰性求值（PEP 649），因此导入模块**不会**报错（实测 `import internal.handler.app_handler` 正常）；但在 Python 3.13 及更早版本，或者代码显式调用 `typing.get_type_hints()` 时，会抛 `NameError: name 'UUID' is not defined`。为了可移植和可读，建议补上 `from uuid import UUID`（课程版本就有这一行）。

对照旧写法 `completion()`：

```python
client = OpenAI(base_url=os.getenv("OPENAI_API_BASE"))
completion = client.chat.completions.create(model="deepseek-flash", messages=[
    {"role": "system", "content": "你是OpenAI开发的聊天机器人，请根据用户的输入回复对应的信息"},
    {"role": "user", "content": req.query.data},
])
content = completion.choices[0].message.content
```

痛点：手工拼 messages、手动抠 `choices[0].message.content`、没有解析器、无法一行切流式。`debug()` 把这些抽象成组件（详见 05 篇）。

### 5.3 服务：`internal/service/app_service.py`

```python
def get_app(self, id: uuid.UUID) -> App:
    return self.db.session.get(App, id)

def update_app(self, id: uuid.UUID) -> App:
    with self.db.auto_commit():
        app = self.get_app(id)
        app.name = "zt聊天机器人"
    return app
```

| 写法 | 状态 | 说明 |
| --- | --- | --- |
| `db.session.get(App, id)` | 推荐（SQLAlchemy 1.4+/2.0） | 按主键查，命中 identity map |
| `db.session.query(App).get(id)` | legacy（课程写法） | 2.0 起不推荐 |
| `query(App).filter_by(...).first()` | 通用 | 任意条件 |

`auto_commit`（`pkg/sqlalchemy/sqlalchemy.py`）：

```python
@contextmanager
def auto_commit(self):
    try:
        yield
        self.session.commit()
    except Exception as e:
        self.session.rollback()
        raise e
```

成功自动 commit，异常自动 rollback 并上抛。**只读查询不要包**，否则多发一次 commit。

### 5.4 模型：`internal/model/app.py`

```python
class App(db.Model):
    __tablename__ = "app"
    __table_args__ = (
        PrimaryKeyConstraint("id", name="pk_app_id"),
        Index("idx_app_account_id", "account_id")
    )

    id = Column(UUID, default=uuid.uuid4, nullable=False)
    account_id = Column(UUID, nullable=False)
    name = Column(String(255), default="", nullable=False)
    icon = Column(String(255), default="", nullable=False)
    description = Column(Text, default="", nullable=False)
    status = Column(String(255), default="", nullable=False)
    updated_at = Column(DateTime, default=datetime.now, onupdate=datetime.now, nullable=False)
    created_at = Column(DateTime, default=datetime.now, nullable=False)
```

- `UUID` 主键可客户端预生成、不可枚举；`default=uuid.uuid4` 传**函数对象**，每次插入调用一次（写成 `uuid.uuid4()` 会在导入时固定成一个值）；
- **`default_factory` 是 dataclass 的写法**（如 `Response.data = field(default_factory=dict)`），SQLAlchemy 用 `default=`/`onupdate=`，别混；显式命名主键约束与索引便于排错。

### 5.5 校验：`internal/schema/app_schema.py`

```python
class CompletionReq(FlaskForm):
    query = StringField("query", validators=[
        DataRequired(message="用户的提问是必填"),
        Length(max=2000, message="用户的提问最大长度是2000"),
    ])
```

数据来源：`FlaskForm` 构造时若未显式传 `formdata`，会依次尝试 `request.form` → `request.files` → `request.json`（JSON 被包成类 MultiDict）。具体行为随 `flask_wtf` 版本略有差异，但结论是 **`CompletionReq()` 能直接读到 JSON body**。

两个细节：**必须关 CSRF**（`validate()` 第一步是 `validate_csrf()`，JSON 请求不带 token，所以 `WTF_CSRF_ENABLED=False`）；**`errors` 结构**为 `{"字段": ["错误1", ...]}`，`validate_error_json` 取第一条作 `message`、整体放 `data`。另外 `DataRequired` 视空字符串为未填写，所以 `{"query": ""}` 也会报错。

### 5.6 响应：`pkg/response/response.py`

```python
@dataclass
class Response:
    code: HttpCode = HttpCode.SUCCESS
    message: str = ""
    data: Any = field(default_factory=dict)

def success_json(data: Any = None):
    return jsonify(Response(code=HttpCode.SUCCESS, message="", data=data))

def validate_error_json(errors: dict = None):
    first_key = next(iter(errors))
    msg = errors.get(first_key)[0] if first_key is not None else ""
    return jsonify(Response(code=HttpCode.VALIDATE_ERROR, message=msg, data=errors))
```

统一格式：`{"code": "success", "message": "", "data": {"content": "..."}}`。

- `HttpCode(str, Enum)` 是 `str` 子类，序列化为 `"success"`/`"fail"`/`"validate_error"` 字符串；
- `default_factory=dict` 避免所有实例共享同一个可变字典；
- `jsonify(dataclass)` 可用，因为 Flask 3 默认 JSON Provider 会用 `dataclasses.asdict()`；
- **业务码在 body 里，HTTP 状态码恒为 200**（除非框架层 404/500），前端不能只看 `response.status`。

### 5.7 异常：`internal/exception` + `internal/server/http.py`

```python
class CustomException(Exception):
    code: HttpCode = HttpCode.FAIL
    message: str = ""
    data: Any = None

    def __init__(self, message: str = None, data: Any = None):
        super().__init__()
        self.message = message
        self.data = data

class NotFoundException(CustomException):
    code = HttpCode.NOT_FOUND
```

子类只改 `code` 类属性即获得语义。全局处理：

```python
def _register_error_handler(self, error: Exception):
    if isinstance(error, CustomException):
        return json(Response(code=error.code, message=error.message,
                             data=error.data if error.data is not None else {}))
    if self.debug or os.getenv("FLASK_ENV") == "development":
        raise error
    return json(Response(code=HttpCode.FAIL, message=str(error), data={}))
```

**debug 模式下 `raise error` 的副作用**：`app.run(debug=True)` 时非自定义异常被重新抛出，交给 Werkzeug 调试中间件，输出 **HTML 500**，浏览器常报：

```text
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

这**不是跨域问题**，而是 500 响应没经过 Flask-CORS 的 `after_request`。排查：DevTools Network 看 Status 是否 500、Preview 是否 Werkzeug 页面、后端终端是否有堆栈。

建议改为始终返回 JSON 并记录堆栈，这样前端永远拿到 JSON，CORS 头也永远存在：

```python
if isinstance(error, CustomException):
    return json(Response(code=error.code, message=error.message, data=error.data or {}))
current_app.logger.exception("未捕获异常")
return json(Response(code=HttpCode.FAIL, message=str(error), data={}))
```

### 5.8 CORS 要点

```python
CORS(self, resources={
    r"/*": {
        "origins": "*",
        "supports_credentials": True,
        # "methods": ["GET", "POST"],
        # "allow_headers": ["Content-Type"],
    }
})
```

| 参数 | 含义 | 注意 |
| --- | --- | --- |
| `origins` | 允许来源 | `"*"` 任意 |
| `supports_credentials` | 允许带 Cookie | 与 `"*"` 有规范冲突，Flask-CORS 会回显请求 Origin；生产建议写明确域名 |
| `methods` | 允许方法 | 当前注释（默认全开） |
| `allow_headers` | 允许头 | 当前注释（默认全开） |

课程曾把 `methods` 限定为 `["GET","POST"]`，后果是 `PUT`/`DELETE` 的 **`OPTIONS` 预检**失败，真正的请求根本发不出去。本地保持注释；若收紧，至少要写 `"methods": ["GET","POST","PUT","DELETE","OPTIONS"]` 并补 `"allow_headers": ["Content-Type","Authorization"]`。

## 六、配置体系

```text
.env ──load_dotenv()──▶ os.environ ──Config.__init__──▶ conf（大写属性）
                                                        │
                             Flask.config.from_object(conf) → app.config
```

- `default_config.py`：兜底默认值；
- `config.py`：读 env + 类型转换（`int()`、`_get_bool_env()`）；
- `from_object`：只搬大写属性。

`_get_bool_env` 只认 `"true"`：

```python
value = _get_env(key)
return value.lower() == "true" if value is not None else False
```

`"1"`、`"yes"`、`"on"` 全是 `False`——这也是 `DEFAULT_CONFIG` 里写字符串 `"False"` 而不是布尔 `False` 的原因（否则 `.lower()` 会报错）。

### `.env` 变量分类（只列名）

| 分类 | 变量 | 用途 |
| --- | --- | --- |
| Flask | `FLASK_DEBUG`、`FLASK_ENV` | 调试开关、环境标识 |
| 表单 | `WTF_CSRF_ENABLED` | JSON API 必须 `False` |
| 数据库 | `SQLALCHEMY_DATABASE_URI`、`SQLALCHEMY_POOL_SIZE`、`SQLALCHEMY_POOL_RECYCLE`、`SQLALCHEMY_ECHO` | 连接串、连接池、SQL 日志 |
| 大模型 | `OPENAI_API_BASE` | 兼容接口地址 |
| 大模型（本地缺失） | `OPENAI_API_KEY` | 需自行补 `<你的密钥>` |
| LangSmith（本地缺失） | `LANGCHAIN_API_KEY`、`LANGCHAIN_PROJECT`、`LANGCHAIN_ENDPOINT`、`LANGCHAIN_TRACING_V2` | 课程有前三项，本地没有 |

连接串写法（值自己填，不要写进仓库）：

```ini
SQLALCHEMY_DATABASE_URI=postgresql+psycopg://<用户>:<密码>@localhost:5432/llmops?client_encoding=utf8
```

`+psycopg` 是 SQLAlchemy 的 psycopg3 驱动；课程写的是 `postgresql://`（默认 psycopg2），装依赖时别装错。

### `OPENAI_API_BASE` / `OPENAI_API_KEY` 的消费方

两个消费者：

1. **代码手动读取**：`completion()` 里 `OpenAI(base_url=os.getenv("OPENAI_API_BASE"))`；
2. **LangChain 自动读取**：

```text
base_url: 显式 → OPENAI_API_BASE → OPENAI_BASE_URL → 官方
api_key : 显式 → OPENAI_API_KEY
```

只配了 base 没配 key 时，`debug()` 里的 `ChatOpenAI` 会报 Missing credentials。**补 `OPENAI_API_KEY=<你的密钥>` 是跑通 `/apps/<uuid>/debug` 的前提。**

## 七、数据库与迁移

分工：SQLAlchemy 负责 ORM（类 ↔ 表、生成 SQL）；Alembic 负责表结构版本与升级/降级脚本；Flask-Migrate 把它包装成 `flask db xxx` 命令。`internal/extension/migrate_extension.py` 创建 `migrate = Migrate()`；`http.py` 指定 `directory="internal/migration"`（不是默认的 `migrations/`）。

### 标准流程

```bash
flask --app app.http.app db init -d internal/migration   # 首次
flask --app app.http.app db migrate -m "create app table"
flask --app app.http.app db upgrade
flask --app app.http.app db downgrade                    # 回滚一步
```

- 必须在**项目根目录**执行，否则找不到 `.env` 和 `internal`；
- `migrate` 只生成脚本，`upgrade` 才改库；
- 生成的脚本要**打开检查**：Alembic 不识别列重命名（会变成删一列+加一列，数据丢失）。

本地已有 `internal/migration/versions/e98a310adbfe_create_app_table.py`，`down_revision = None`，唯一 head。

### 为什么不要拷课程迁移文件

课程有两条 revision：`858200175b1f`（根，`down_revision=None`）→ `09b68127ca41`。直接拷进本地 `versions/`，加上本地已有的 `e98a310adbfe`（根也是 `None`），Alembic 会看到多个根/多个 head，报 `Multiple head revisions are present for given argument 'head'`，或 `Can't locate revision identified by '858200175b1f'`。

正确做法：**只迁移模型代码**，让 Alembic 按本地模型重新 autogenerate。学习阶段不值得用 `flask db merge heads` 硬合。

## 十、自测题（5 道）

1. 为什么必须用 `python -m app.http.app`？如果一定要 `python app/http/app.py`，代码怎么改？
2. `load_dotenv()` 为什么必须在 `Config()` 之前？把配置写成类属性会怎样？
3. `POST /apps/not-a-uuid/debug` 返回什么？会进 `AppHandler.debug` 吗？
4. 前端报 CORS 错误，但 Network 里状态码是 500、Preview 是 Werkzeug 页面。根因与改法？
5. 把课程两个迁移脚本拷进 `versions/` 后 `flask db upgrade` 报 `Multiple head revisions`，为什么？两种解决思路？

<details>
<summary>参考答案要点</summary>

1. 相对导入需要 `__package__`，直接运行脚本时为 `None`。改成绝对导入 `from app.http.module import ExtensionModule` 可运行，但仍建议 `-m`。
2. `Config.__init__` 才 `os.getenv`；类属性在 import 时求值，早于 `load_dotenv`，读到 `None`。
3. 404，不进 Handler；`<uuid:app_id>` 转换器校验失败直接不匹配路由。
4. `debug=True` 时非自定义异常被 `raise`，响应交给 Werkzeug 调试页，绕过 Flask 的 `after_request`，没有 CORS 头。改为始终返回 JSON 并记录日志。
5. 两个脚本都以 `None` 为根，加上本地 `e98a310adbfe` 形成多个 head。思路一：删掉拷贝文件，按本地模型重新 `migrate`；思路二：`flask db merge heads`（不推荐）。

</details>
