# 03 前端架构与聊天页联动

> 前两篇讲「工具怎么配」，这一篇讲「代码怎么跑」：从 `index.html` 到聊天页发出第一条消息。

## 读完你能做什么

- 说清从 `index.html` 到页面渲染的完整启动顺序，知道少注册一个东西会怎样「静默坏掉」。
- 看懂两套 Layout 分组、路由守卫和 `app_id` 参数。
- 理解 Pinia setup store 与跨页面共享。
- 画出「页面 → service → request → 后端 → 返回」的数据流。
- 逐段读懂聊天页 `DetailView.vue`，并知道自动滚动该怎么补。


## 一、应用启动链路

### 1. `index.html`

```html
<div id="app"></div>
<script type="module" src="/src/main.ts"></script>
```

`#app` 是挂载点；`/src/main.ts` 是 Vite 分析依赖的起点。

### 2. `src/main.ts`

```ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import ArcoVue from '@arco-design/web-vue'
import ArcoVueIcon from '@arco-design/web-vue/es/icon'

import App from '@/App.vue'
import router from '@/router'

import '@arco-design/web-vue/dist/arco.css'
import './style.css'

const app = createApp(App)

app.use(createPinia())
app.use(router)
app.use(ArcoVue)
app.use(ArcoVueIcon)

app.mount('#app')
```

| 步骤 | 作用 | 少了会怎样 |
| --- | --- | --- |
| `createApp(App)` | 创建应用 | 无应用可挂载 |
| `use(createPinia())` | 注册 Pinia | `useCounterStore()` 报「no active Pinia」 |
| `use(router)` | 注册路由 | `<router-view />` 不渲染，地址变化无反应 |
| `use(ArcoVue)` | 全局注册 `a-*` 组件 | 组件变成未知标签 |
| `use(ArcoVueIcon)` | 全局注册 `icon-*` 图标 | 图标位置空白 |
| `mount('#app')` | 挂载 | 页面空白 |

Vue 对未注册组件**不抛异常**，只在控制台警告：

```text
[Vue warn]: Failed to resolve component: a-button
```

页面上按钮变成一个没有样式的 `<a-button>` 标签。新手常误以为是 Tailwind 坏了，其实是组件没注册。图标同理：只注册 `ArcoVue` 不注册 `ArcoVueIcon`，按钮正常、图标空白。

### 3. CSS 顺序

先 `arco.css`，后 `style.css`：组件库的 reset、CSS 变量先就位，项目自己的 `body` 字体和 `@theme` 后加载，属于「最后拍板」的一层。

但要记住：**不要指望只靠 import 顺序覆盖 Arco 组件内部样式**。Tailwind v4 的工具类在 CSS `@layer` 里，Arco 的样式未分层；按级联规则，未分层声明优先。改组件内部样式优先用 Arco 的 CSS 变量或 `:deep()`。

### 4. 启动流程

```text
index.html
  └── main.ts
        ├── createApp(App)
        ├── use(Pinia / Router / ArcoVue / ArcoVueIcon)
        ├── 加载 arco.css → style.css
        └── mount('#app')
              └── App.vue
                    └── <router-view />      第一层出口：Layout
                          └── <router-view /> 第二层出口：页面
```


## 二、路由设计

`src/router/index.ts` 的结构（省略部分 import）：

```ts
const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      component: DefaultLayout,
      children: [
        { path: '', redirect: 'home' },
        { path: 'home', name: 'pages-home', component: () => import('@/views/pages/HomeView.vue') },
        { path: 'space/apps', name: 'space-apps-list', component: () => import('@/views/space/apps/ListView.vue') },
      ],
    },
    {
      path: '/',
      component: BlankLayout,
      children: [
        { path: 'auth/login', name: 'auth-login', component: () => import('@/views/auth/LoginView.vue') },
        { path: 'space/apps/:app_id', name: 'space-apps-detail', component: () => import('@/views/space/apps/DetailView.vue') },
      ],
    },
  ],
})

router.beforeEach(async (to) => {
  if (!isLogin() && to.name != 'auth-login') {
    return { path: '/auth/login' }
  }
})
```

| Layout | 子 path | 完整 URL | name |
| --- | --- | --- | --- |
| DefaultLayout | `''` | `/` → 重定向 `home` | — |
| DefaultLayout | `home` | `/home` | `pages-home` |
| DefaultLayout | `space/apps` | `/space/apps` | `space-apps-list` |
| BlankLayout | `auth/login` | `/auth/login` | `auth-login` |
| BlankLayout | `space/apps/:app_id` | `/space/apps/xxx` | `space-apps-detail` |

### 1. 两个 `'/'` 为什么不冲突

真正参与匹配的是「父路径 + 子路径」拼出的完整路径。`/space/apps` 和 `/space/apps/:app_id` 是两条不同路径，各自只在一个分组里存在，所以能落到正确的 Layout。

### 2. `/` 重定向

子路由 `{ path: '', redirect: 'home' }` 把根路径送到 `/home`。不写的话，访问 `/` 会匹配到 Layout 但子出口为空，页面只剩外壳。

### 3. 守卫

`isLogin()` 在 `src/utils/auth.ts` 里目前固定返回 `true`：

```ts
export const isLogin = () => {
  // todo:授权认证逻辑待实现
  return true
}
```

所以守卫目前永远放行；`// todo:路由守卫逻辑还未实现` 是早期注释，骨架已经有了，缺的是真正的登录态判断。`to.name != 'auth-login'` 用来避免在登录页无限重定向。守卫只声明 `to` 不声明 `from`，是因为 `noUnusedParameters` 不允许未使用参数（见 02 篇）。

### 4. `app_id` 必须两边一致

路由写 `space/apps/:app_id`，组件就必须取 `route.params.app_id`。写成 `params.appId` 会得到 `undefined`，请求变成 `/apps/undefined/debug`，后端 `uuid` 转换器直接 404。这是最常见的低级错误。

`route.params` 类型是 `string | string[]`，所以代码用 `as string`；更稳的是 `String(route.params.app_id ?? '')`。

### 5. 为什么聊天页用 BlankLayout

`DefaultLayout` 有侧边栏，适合后台页面；聊天页要全屏左右分栏，套侧边栏会挤压布局，所以放在只有 `<router-view />` 的 `BlankLayout` 下。


## 三、Layout 与根组件

`App.vue` 只保留一个出口：

```vue
<template>
  <router-view />
</template>
```

页面外壳交给 Layout。若把侧边栏写进 `App.vue`，登录页也会带着侧边栏，还得用 `v-if` 判断路由，逻辑越写越乱。

```vue
<!-- src/views/layouts/DefaultLayout.vue -->
<template>
  <nav>侧边栏</nav>
  <router-view />
</template>
```

- Vue 3 支持多根节点，`nav` 和 `router-view` 可以并列。
- 第二个 `<router-view />` 是嵌套路由出口，子页面渲染在这里。

```vue
<!-- src/views/layouts/BlankLayout.vue -->
<template>
  <router-view />
</template>
```

只做透传，给全屏页面用。两个 Layout 都保留了空的 `<style scoped></style>`，所以 Stylelint 关了 `no-empty-source`。


## 四、Pinia 状态管理

### 1. setup store

```ts
// src/stores/counter.ts
export const useCounterStore = defineStore('counter', () => {
  const count = ref(0)                              // state
  const doubleCount = computed(() => count.value * 2) // getter
  function increment() { count.value++ }            // action
  return { count, doubleCount, increment }          // 必须 return
})
```

`defineStore` 的第一个参数是唯一 id；两个文件用同一个 id 会指向同一个 store。

### 2. 消费与跨页面共享

```vue
<!-- src/views/space/apps/ListView.vue -->
<script setup lang="ts">
import { useCounterStore } from '@/stores/counter'
const counterStore = useCounterStore()
</script>

<template>
  <p>数值是:{{ counterStore.count }}</p>
</template>
```

模板里直接 `counterStore.count`，自动解包，不需要 `.value`。当前没有任何页面调用 `increment()`，所以列表页永远显示 0，这是占位示例。

跨页面共享看 `account` store：内部用 `ref` 存 `{ name, email, avatar }`，提供 `update(params)`（`Object.assign` 合并）和 `clear()`（恢复初始值）。`HomeView.vue` 点「更新名字」→ 跳到 `/space/apps` → 再回 `/home`，名字仍是「小小课」。数据在 Pinia 里，页面卸载不会清空；刷新浏览器才恢复初始值，因为 Pinia 只在内存中。

`update(params: any)` 是**显式 any**，ESLint 规则已关闭所以通过；写成 `function update(params)` 会触发隐式 any，TypeScript 报错。


## 五、请求层

### 1. 分工

`config/index.ts` 放后端地址与状态码，`models/` 放类型，`utils/request.ts` 封装 fetch，`services/` 放业务接口，页面只调用 service。

### 2. 配置与类型

```ts
// src/config/index.ts
export const apiPrefix: string = 'http://localhost:5000'
export const httpCode = { success: 'success', /* ... */ }
```

```ts
// src/models/base.ts
export type BaseResponse<T> = { code: string; message: string; data: T }

// src/models/app.ts
import { type BaseResponse } from '@/models/base'
export type DebugAppResponse = BaseResponse<{ content: string }>
```

后端 `success_json({"content": ...})` 返回：

```json
{ "code": "success", "message": "", "data": { "content": "模型回复" } }
```

泛型 `T` 就是 `data` 的形状。`DebugAppResponse` 让 `response.data.content` 有字符串类型；写成 `BaseResponse<any>` 就退回 `any`，字段写错也不报错。

### 3. `request.ts` 的核心

```ts
const TIME_OUT = 100000
const baseFetchOptions = {
  method: 'GET', mode: 'cors', credentials: 'include',
  headers: new Headers({ 'Content-Type': 'application/json' }), redirect: 'follow',
}

// GET 且带 params → 拼 ?a=1&b=2（encodeURIComponent）
// POST 有 body → JSON.stringify
return Promise.race([
  new Promise((resolve, reject) => setTimeout(() => reject('接口已超时'), TIME_OUT)),
  new Promise((resolve, reject) => {
    globalThis.fetch(urlWithPrefix, options as RequestInit).then(async (res) => {
      const json = await res.json()
      if (json.code === httpCode.success) resolve(json)
      else { Message.error(json.message); reject(new Error(json.message)) }
    }).catch((err) => { Message.error(err.message); reject(err) })
  }),
]) as Promise<T>
```

- `mode: 'cors'` + `credentials: 'include'`：前端 5173、后端 5000 跨域，且要带 Cookie；后端 CORS 必须允许凭证。
- `Promise.race` 做 100 秒超时。
- HTTP 200 不代表业务成功，必须判断 `json.code === 'success'`。
- `Message.error` 在请求层统一弹，所以页面里不需要重复 catch。

### 4. service

```ts
// src/services/app.ts
export const debugApp = (app_id: string, query: string) => {
  return post<DebugAppResponse>(`/apps/${app_id}/debug`, { body: { query } })
}
```

`post<T>` → `request<T>` → `baseFetch<T>`，泛型一路传到底。

### 5. 数据流

```text
DetailView.send()
  └── debugApp(app_id, "你好")
        └── post('/apps/<id>/debug', { body: { query: '你好' } })
              └── request → baseFetch
                    └── fetch http://localhost:5000/apps/<id>/debug
                          └── Flask：校验 query → 调大模型 → success_json
                    ◄── { code: 'success', data: { content } }
              ◄── 判断 code 通过，resolve
        ◄── response: DebugAppResponse
  └── response.data.content → push 到 messages → 渲染 AI 气泡
```


## 六、聊天页 `DetailView.vue`

### 1. script

```ts
const query = ref('')
const messages = ref<any[]>([])
const isLoading = ref(false)
const route = useRoute()

const clearMessages = () => { messages.value = [] }

const send = async () => {
  if (!query.value) { Message.error('用户提问不能为空'); return }
  if (isLoading.value) { Message.warning('上一次回复还未结束，请稍等'); return }

  try {
    const humanQuery = query.value
    messages.value.push({ role: 'human', content: humanQuery })
    query.value = ''
    isLoading.value = true

    const response = await debugApp(route.params.app_id as string, humanQuery)
    messages.value.push({ role: 'ai', content: response.data.content })
  } finally {
    isLoading.value = false
  }
}
```

执行顺序：

1. 空输入、重复发送两道校验；
2. **先 push 人类消息**，再清空输入框——用户立刻看到自己说的话；
3. 置 `isLoading`，显示加载动画并防连点；
4. `await` 请求；
5. 取 `response.data.content`，push AI 消息；
6. `finally` 一定复位 loading，成功失败都不会卡住。

没有 `catch` 不是忘了：`request.ts` 已经弹过 `Message.error`，页面再 catch 会弹两次。`finally` 仍然执行。

消息结构：

```ts
{ role: 'human', content: '用户说的话' }
{ role: 'ai',    content: 'AI 回复的内容' }
```

### 2. 模板渲染

```vue
<div class="flex flex-row gap-2 mb-6" v-for="message in messages" :key="message.content">
  <a-avatar v-if="message.role === 'human'" :size="30" :style="{ backgroundColor: '#3370ff' }">慕</a-avatar>
  <a-avatar v-else :size="30" :style="{ backgroundColor: '#00d0b6' }"><icon-apps /></a-avatar>
  <div class="flex flex-col gap-2">
    <div class="font-semibold text-gray-700">{{ message.role === 'human' ? '慕小课' : 'ChatGPT聊天机器人' }}</div>
    <div v-if="message.role === 'human'" class="max-w-max bg-blue-700 text-white border border-blue-800 px-4 py-3 rounded-2xl leading-5">{{ message.content }}</div>
    <div v-else class="max-w-max bg-gray-100 text-gray-900 border border-gray-200 px-4 py-3 rounded-2xl leading-5">{{ message.content }}</div>
  </div>
</div>
```

- `v-for` + `v-if/v-else` 按 `role` 切换头像、昵称、气泡配色。
- `:key="message.content"` 用内容当 key。**连续发两条相同的话会 key 重复**，Vue 警告且可能渲染错乱；改用 `index` 或唯一 `id` 更稳。
- 空状态 `v-if="!messages.length"` 显示大图标和标题；加载状态 `v-if="isLoading"` 显示 `<icon-loading />` 气泡。

### 3. 输入区

```vue
<input type="text" class="flex-1 outline-0" v-model="query" @keyup.enter="send" />
<a-button type="text" shape="circle" @click="send"><template #icon><icon-send size="16" :style="{ color: '#1d4ed8' }" /></template></a-button>
```

- `v-model="query"` 双向绑定；`@keyup.enter="send"` 回车发送。
- 清除按钮调用 `clearMessages`；`+` 按钮目前只是装饰，没有绑定事件。
- 发送按钮**没有禁用**，而是在 `send()` 里用 `Message.warning` 拦重复请求；也可以改成 `:disabled="isLoading"`，更直观。

### 4. 还缺的一步：自动滚动

当前代码**没有实现自动滚动**。消息多了，新消息会出现在可视区下方，需要手动往下滚。

补法三件套：

```ts
import { nextTick, ref } from 'vue'

const messageContainer = ref<HTMLDivElement | null>(null)

const scrollToBottom = async () => {
  await nextTick()
  const el = messageContainer.value
  if (!el) return
  el.scrollTo({ top: el.scrollHeight, behavior: 'smooth' })
}
```

```vue
<div ref="messageContainer" class="h-full min-h-0 px-6 py-7 overflow-x-hidden overflow-y-scroll scrollbar-w-none">
```

在 `send()` 里 push 人类消息后、push AI 消息后各调用一次 `await scrollToBottom()`。

**为什么必须 `nextTick`**：Vue 的 DOM 更新是异步的，改完 `messages` 立刻读 `scrollHeight` 拿到的还是旧高度，会差一截。`nextTick()` 等到本轮 DOM 更新完成再滚。

`<script setup>` 里变量名必须和模板 `ref="messageContainer"` 完全一致，Vue 才能自动绑定。

## 七、布局关键 CSS

```vue
<div class="min-h-screen">
  <header class="flex items-center h-[74px] bg-gray-100 ...">顶部导航</header>
  <div class="flex flex-row h-[calc(100vh-74px)]">
    <div class="w-2/3 bg-gray-50 h-full">...</div>
    <div class="flex flex-col w-1/3 bg-white h-full">
      <header class="flex flex-shrink-0 items-center h-16 ...">调试与预览</header>
      <div class="h-full min-h-0 px-6 py-7 overflow-x-hidden overflow-y-scroll scrollbar-w-none">...</div>
      <div class="w-full flex-shrink-0 flex flex-col">输入区</div>
    </div>
  </div>
</div>
```

| 类名 | 含义 / 为什么需要 |
| --- | --- |
| `min-h-screen` | 内容少时背景也铺满全屏 |
| `h-[74px]` | 顶栏固定 74px；Tailwind 没这个预设，用任意值 |
| `h-[calc(100vh-74px)]` | 内容区 = 视口高 − 顶栏高，正好一屏 |
| `w-2/3` / `w-1/3` | 左编排、右聊天 2:1 |
| `h-16` | 64px，右栏标题高度 |
| `h-[calc(100%-64px)]` | 左栏标题 64px，下面占满剩余 |
| `flex-shrink-0` / `shrink-0` | 顶栏、输入区不被压缩 |
| `min-h-0` | **允许 flex 子项缩到内容高度以下**（关键） |
| `overflow-y-scroll` | 消息超出时只滚消息区 |
| `scrollbar-w-none` | 隐藏滚动条，来自 `@utility` |

### `min-h-0` 解决什么

flex 子项默认 `min-height: auto`，不能比内容矮。消息越堆越多，消息区拒绝缩小，把右栏撑高，最终整页滚动、输入框被顶出屏幕。

加 `min-h-0` 告诉浏览器「可以比内容矮，超出我自己 overflow 处理」，消息区被限制在剩余空间内，内部滚动生效，输入框固定底部。

固定套路：

```text
父容器：flex flex-col + 固定总高
滚动区：h-full + min-h-0 + overflow-y-auto
固定区：shrink-0
```

`scrollbar-w-none` 不是内置类，来自 `src/style.css` 的 `@utility scrollbar-w-none { scrollbar-width: none; }`。滚动条又出现时，先检查它还在不在、`style.css` 有没有被引入。


## 八、类型与健壮性

- 泛型链路：`debugApp` → `post<T>` → `request<T>` → `baseFetch<T>`，最终 `response.data.content` 是 `string`，字段拼错会报错。
- `import { type DebugAppResponse }` 的 `type` 是 `verbatimModuleSyntax` 要求的；`route.params.app_id` 是 `string | string[]`，用 `as string` 或 `String(...)` 兜底；后端不可控时用 `response.data?.content ?? ''`。

## 九、常见错误对照表

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 页面出现 `<a-button>` 原始标签 | 没注册 `ArcoVue` | `main.ts` 里 `app.use(ArcoVue)` |
| 按钮正常但图标空白 | 没注册 `ArcoVueIcon` | `app.use(ArcoVueIcon)` |
| `h-16`、`px-4` 全失效 | 引入了课程 v3 `main.css`，或没引入 `style.css` | 改为 `import './style.css'`，确认首行 `@import 'tailwindcss'` |
| 访问 `/` 空白 | 子路由没 redirect | 加 `{ path: '', redirect: 'home' }` |
| 一直跳登录页/死循环 | `to.name` 拼错或没排除登录页 | 保证 name 与判断一致 |
| 请求 `/apps/undefined/debug` | 路由参数名与取值名不一致 | `:app_id` ↔ `params.app_id` |
| 新消息不滚到底 | 没写自动滚动或没 `nextTick` | 加 `nextTick` + `scrollTo` |
| 整页滚动、输入框被顶走 | 滚动区缺 `min-h-0` | 加 `min-h-0` + `overflow-y-auto` |
| 中文输入法回车误发送 | `@keyup.enter` 在组合输入阶段也触发 | 加 `compositionstart/end` 判断 |
