## 一、LangChain 的回调

### 1.1 StdOutCallbackHandler

开启回调后观察链的每一步：

```python
resp = chain.stream(
    "你好，你是？",
    config={"callbacks": [StdOutCallbackHandler(), LLMOpsCallbackHandler()]}
)
for chunk in resp:
    pass
```

它打印链上每环的输入输出、提示词、模型原始响应，排查「模型到底收到了什么」很有效。传法两种，等价：

```python
chain.invoke(x, config={"callbacks": [handler]})          # 调用时
chain.with_config({"callbacks": [handler]}).invoke(x)     # 链上绑定
```

### 1.2 自定义 Handler 统计耗时

```python
class LLMOpsCallbackHandler(BaseCallbackHandler):
    """自定义LLMOps回调处理器"""
    start_at: float = 0

    def on_chat_model_start(self, serialized, messages, *, run_id, **kwargs) -> Any:
        print("messages:", messages)      # 最终发给模型的消息列表
        self.start_at = time.time()

    def on_llm_end(self, response: LLMResult, *, run_id, **kwargs) -> Any:
        print("完整输出:", response)
        print("程序消耗:", time.time() - self.start_at)
```

- 两时间戳相减 = 模型耗时，可上报监控；`run_id`/`parent_run_id` 把回调串成调用树；
- 注意：`on_chat_model_start` 只对 ChatModel 触发；纯文本 LLM 走 `on_llm_start`。

### 1.3 LangSmith

开启后每次链执行都会上传完整 trace。需要的变量：

```ini
LANGCHAIN_TRACING_V2=true
LANGCHAIN_API_KEY=<你的密钥>
LANGCHAIN_PROJECT=llmops-api
LANGCHAIN_ENDPOINT=https://api.smith.langchain.com
```

现状：课程 `.env` 有 `LANGCHAIN_ENDPOINT`、`LANGCHAIN_API_KEY`、`LANGCHAIN_PROJECT`，但**没有** `LANGCHAIN_TRACING_V2`；本地 `.env` **一项都没有**。所以当前未开启追踪，想开四行都要补（缺 `TRACING_V2` 不会上传）。

## 二、不用 LangChain 时：在每个调用点手动埋点

没有回调机制，日志和计时只能写在业务代码里：

```python
import time

def chat_with_logging(messages: list[dict]) -> str:
    print("messages:", messages)              # 想知道的输入
    start_at = time.time()
    try:
        resp = client.chat.completions.create(
            model="deepseek-flash",
            messages=messages,
        )
        return resp.choices[0].message.content or ""
    finally:
        print("完整输出:", resp)
        print("程序消耗:", time.time() - start_at)
```

流式版本还要自己判断“哪一块是最后一块”：

```python
start_at = time.time()
buffer: list[str] = []
for chunk in client.chat.completions.create(model="deepseek-flash", messages=messages, stream=True):
    delta = chunk.choices[0].delta.content
    if delta:
        buffer.append(delta)
print("完整输出:", "".join(buffer))
print("程序消耗:", time.time() - start_at)
```

逐项对照：

| 能力 | LangChain | 手写 openai SDK |
| --- | --- | --- |
| 埋点位置 | 一处 `config={"callbacks": [...]}`，全链生效 | 每个调用点都要复制一段 try/finally |
| 覆盖范围 | 链上每一环（模板渲染、模型调用、解析）都有事件 | 只能覆盖自己手动包住的那几行 |
| 嵌套关系 | `run_id` / `parent_run_id` 自动组成调用树 | 自己传上下文变量维护层级 |
| 流式结束 | `on_llm_end` 统一触发 | 自己判断迭代结束，再补一段统计 |
| 上报平台 | LangSmith 打开开关即上传 | 自己对接日志平台 / 链路追踪系统 |
| 业务代码侵入 | 无（业务只调 `invoke`） | 有（日志、计时和业务混在一起） |

手写当然也能观测，代价是**每一处调用都要重写一遍**，而且链一长就没有统一的“整条链耗时”视图。回调机制真正解决的是这两点。
