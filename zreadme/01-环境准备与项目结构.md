## 一、先认清三个目录

很多人一开始会把「课程源码」和「自己写的项目」混在一起改，最后两边都乱。先把定位钉死：

| 目录 | 角色 | 能不能改 | 说明 |
| --- | --- | --- | --- |
| `D:\python\llmops\llmops-ui` | 你从零搭起来的**本地前端** | 能改，这是你的主战场 | Vue3 + Vite 8 + TS6 + Tailwind v4，版本比课程新 |
| `D:\python\llmops\llmops-api` | 你从零搭起来的**本地后端** | 能改 | Python / Flask，默认监听 `127.0.0.1:5000`，给前端提供接口 |
| `D:\python\llmops\第3周\第2章 实现联动第一个带UI的聊天机器人\llmops-ui` | **课程源码（只读参考）** | 不建议改 | Vue3 + Vite 5 + TS5 + Tailwind v3，用 yarn 管理，用来对照「老师怎么写的」 |

三者的关系可以用一句话概括：

```text
浏览器
  └── 本地前端 llmops-ui（你写页面、样式、交互）
        └── HTTP 请求 http://localhost:5000
              └── 本地后端 llmops-api（Flask 提供 /apps/<app_id>/debug 等接口）
                    └── 调用大模型（OpenAI 兼容接口）

课程源码 llmops-ui：只用来「抄思路、对差异」，不参与运行
```

> 关键习惯：**迁移时以本地项目为准，课程源码只读**。遇到不一致，先问「是版本差异还是我写错了」，本篇和后续两篇会逐条给答案。

## 三、环境要求

### Node 版本：22+

本项目 `README.md` 写的是：

```bash
# 1. 切换 Node（Vite 8 需要 Node 22+，管理员权限执行）
nvm use 22.13.1
```

本机实际版本：

```bash
node -v   # v22.13.1
pnpm -v   # 12.18.0
```

为什么必须用较新的 Node？

1. **Vite 8 本身要求新 Node**。Vite 的构建/开发服务器大量使用较新的 Node API，Node 16/18 已经跑不起来。
2. **这套工具链是 2024 年之后的新版本**：TypeScript 6、ESLint 10、Stylelint 18、pnpm 12，任何一个都在语法/配置上向前走了，旧 Node 会遇到各种「不支持」。
3. **pnpm 12 有自己的供应链安全策略**（见 02 篇的两个坑），它依赖新版 Node 的行为。

### 包管理器：pnpm 12

课程源码用 `yarn`（目录里有 `yarn.lock`），本地项目统一改用 `pnpm`（目录里有 `pnpm-lock.yaml`）。原因：

- pnpm 用内容寻址的全局 store + 硬链接，装依赖快、占磁盘少。
- 依赖隔离更严格，不会出现「没声明也能 import」的幽灵依赖。
- 本项目额外用到了 pnpm 12 的 `minimumReleaseAgeExclude` 配置，见 02 篇。

> 注意：**不要混用** npm / yarn / pnpm。同一个项目只保留一份锁文件，否则会出现「我这儿能装、你那儿装不上」。

### 编辑器

`.vscode/extensions.json` 里推荐安装 **Vue - Official（Volar）** 插件。没有它，`.vue` 文件里的 TypeScript 不会有类型提示，模板里的 `message.role`、`counterStore.count` 都会显示成 `any`。

## 四、从零创建项目（可照着敲）

下面命令与本地 `package.json` 中的依赖和脚本一一对应。已经建好的项目不用重复执行，复习时当作「这个项目是怎么长出来的」来看。

### 第 1 步：用 Vite 脚手架创建 Vue + TS 项目

```bash
pnpm create vite llmops-ui --template vue-ts
cd llmops-ui
pnpm install
```

`vue-ts` 模板自带：`vue`、`typescript`、`vue-tsc`、`@vitejs/plugin-vue`、`@vue/tsconfig`、`@types/node` 等基础依赖。生成的项目已经有 `index.html`、`src/main.ts`、`src/App.vue`、`vite.config.ts` 和三份 tsconfig。

### 第 2 步：装运行时依赖（会进生产构建）

```bash
pnpm add vue-router pinia @arco-design/web-vue
```

对应 `package.json` 的 `dependencies`：路由、状态管理、组件库。

### 第 3 步：装 Tailwind CSS v4

```bash
pnpm add -D tailwindcss @tailwindcss/vite
```

Tailwind v4 的关键变化：**不再需要** `tailwind.config.js`、`postcss.config.js`、`autoprefixer`。它通过 `@tailwindcss/vite` 插件直接接管，样式入口用一行 `@import 'tailwindcss';`。课程项目里的 `tailwind.config.js` + `postcss.config.js` 是 v3 时代的产物，**不要照搬**。

### 第 4 步：装代码校验工具

```bash
# ESLint 及 Vue/TS 适配
pnpm add -D eslint @eslint/js eslint-plugin-vue @vue/eslint-config-typescript @vue/eslint-config-prettier

# Stylelint 及 Vue 单文件组件支持
pnpm add -D stylelint stylelint-config-standard stylelint-config-recommended-vue stylelint-config-html postcss-html

# 格式化
pnpm add -D prettier

# 提交校验
pnpm add -D husky lint-staged @commitlint/cli @commitlint/config-conventional
```

### 第 5 步：初始化 husky 钩子

```bash
pnpm exec husky init
```

它会创建 `.husky/pre-commit`，并在 `package.json` 里加一条 `"prepare": "husky"`。然后把钩子内容改成：

```bash
# .husky/pre-commit
pnpm exec lint-staged
```

再新建 `.husky/commit-msg`：

```bash
# .husky/commit-msg
pnpm exec commitlint --edit "$1"
```

> `"prepare": "husky"` 的作用：别人 `pnpm install` 之后自动装好 git 钩子，不需要手动再执行一次。

### 第 6 步：创建配置文件

按本地项目的真实文件创建（内容逐行解读见 02 篇）：

| 文件 | 作用 |
| --- | --- |
| `vite.config.ts` | 注册 Vue 插件、Tailwind 插件、`@` 别名 |
| `tsconfig.json` / `tsconfig.app.json` / `tsconfig.node.json` | TypeScript 项目引用与两套环境配置 |
| `eslint.config.js` | ESLint 10 flat config |
| `stylelint.config.js` | 样式检查规则 |
| `.prettierrc.json` / `.prettierignore` | 格式化规则与忽略清单 |
| `commitlint.config.js` | 提交信息规范 |
| `pnpm-workspace.yaml` | pnpm 12 供应链策略豁免 |
| `.editorconfig` / `.gitignore` | 编辑器与 git 的基础约定 |

### 第 7 步：建业务目录并写页面

在 `src` 下创建 `config/`、`models/`、`services/`、`utils/`、`stores/`、`views/{layouts,pages,auth,space/apps}`，然后按 03 篇的顺序写 `main.ts`、路由、布局、页面。

### 第 8 步：启动

```bash
pnpm dev
```

浏览器打开终端输出的地址（Vite 默认 `http://localhost:5173`）。`vite.config.ts` 没有写 `server.port`，所以端口就是 Vite 默认值；如果 5173 被占用，Vite 会自动换下一个可用端口。

## 五、目录结构

### 根目录

```text
llmops-ui/
├── index.html                 # Vite 的 HTML 入口，挂载点是 <div id="app">
├── package.json               # 依赖清单 + npm scripts + lint-staged 配置
├── pnpm-lock.yaml             # pnpm 锁文件，锁定精确版本
├── pnpm-workspace.yaml        # pnpm 12 供应链策略（minimumReleaseAgeExclude）
├── vite.config.ts             # Vite 核心配置
├── tsconfig.json              # 根 tsconfig，只做项目引用
├── tsconfig.app.json          # src 业务代码的 TS 配置
├── tsconfig.node.json         # vite.config.ts 的 TS 配置（Node 环境）
├── eslint.config.js           # ESLint flat config
├── stylelint.config.js        # Stylelint 配置
├── .prettierrc.json           # Prettier 规则
├── .prettierignore            # Prettier 忽略清单
├── commitlint.config.js       # 提交信息校验
├── .editorconfig              # 编辑器基础约定
├── .gitignore                 # git 忽略清单
├── .husky/
│   ├── pre-commit             # 提交前跑 lint-staged
│   └── commit-msg             # 提交信息跑 commitlint
├── public/
│   └── favicon.svg            # 原样拷贝到构建产物的静态资源
└── src/                       # 业务源码（重点，见下）
```

### src 目录

```text
src/
├── main.ts                    # 应用入口：创建 app、注册 Pinia/Router/Arco、挂载
├── App.vue                    # 根组件：只有一个 <router-view />，页面外壳交给 Layout
├── style.css                  # 全局样式入口：@import 'tailwindcss' + @theme + @utility
├── assets/
│   └── logo.svg               # 需要被构建工具处理的静态资源
├── config/
│   └── index.ts               # apiPrefix（后端地址）、httpCode（业务状态码）
├── models/
│   ├── base.ts                # BaseResponse<T>、BasePaginatorResponse<T>
│   └── app.ts                 # DebugAppResponse
├── router/
│   └── index.ts               # 路由表 + beforeEach 守卫
├── services/
│   └── app.ts                 # 业务接口封装：debugApp()
├── stores/
│   ├── counter.ts             # 计数器 store（教程示例）
│   ├── account.ts             # 账号 store（含 update/clear）
│   └── example.ts             # 另一个计数器示例（带 reset）
├── utils/
│   ├── request.ts             # fetch 封装：统一前缀、超时、code 判断、报错提示
│   └── auth.ts                # isLogin()（当前固定返回 true，待实现）
└── views/
    ├── layouts/
    │   ├── DefaultLayout.vue  # 默认外壳：侧边栏 + <router-view />
    │   └── BlankLayout.vue    # 空白外壳：只有 <router-view />，给全屏页面用
    ├── pages/
    │   └── HomeView.vue       # 主页，演示 account store
    ├── auth/
    │   └── LoginView.vue      # 登录页占位
    └── space/
        └── apps/
            ├── ListView.vue   # 应用列表占位，演示 counter store
            └── DetailView.vue # 聊天页（核心页面）
```

### 逐目录说明

| 目录 | 职责 | 写代码时的判断标准 |
| --- | --- | --- |
| `assets/` | 需要被 Vite 处理的静态资源（图片、svg） | 会被打包、可以 import、文件名带 hash |
| `components/` | 可复用的公共组件 | **当前项目还没有创建这个目录**；当同一个组件被两个以上页面用到时再建 |
| `config/` | 全局常量配置 | 后端地址、状态码映射这类「到处都要用」的值 |
| `models/` | 数据类型定义 | 只写 `type` / `interface`，不写运行时代码 |
| `router/` | 路由表与守卫 | 新增页面 = 新增一条 route |
| `services/` | 接口封装 | 一个后端资源一个文件，如 `app.ts` |
| `stores/` | Pinia 状态 | 需要跨页面共享的数据才放这里 |
| `utils/` | 工具函数 | 和业务无关的通用逻辑：请求、登录判断 |
| `views/layouts/` | 页面外壳 | 决定「有没有侧边栏/顶栏」 |
| `views/pages/` | 普通业务页面 | 有外壳的页面 |
| `views/auth/` | 认证相关页面 | 登录、注册 |
| `views/space/apps/` | 应用空间下的页面 | 列表、详情/聊天 |

> 为什么 `public/` 和 `assets/` 要分开？`public/` 里的文件会**原样**拷贝到 `dist`，文件名不变，适合 favicon、robots.txt；`assets/` 里的文件会经过构建处理，适合需要被引用、压缩、加 hash 的图片。

## 六、常用命令

`package.json` 的 `scripts` 是唯一事实来源：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc -b && vite build",
    "preview": "vite preview",
    "lint": "eslint . && stylelint \"src/**/*.{vue,css}\" && prettier --check src/",
    "lint:fix": "eslint . --fix && stylelint \"src/**/*.{vue,css}\" --fix && prettier --write src/",
    "prepare": "husky"
  }
}
```

| 命令 | 背后实际执行了什么 | 什么时候用 |
| --- | --- | --- |
| `pnpm dev` | 启动 Vite 开发服务器，按需编译，支持热更新（HMR） | 日常开发 |
| `pnpm build` | 先 `vue-tsc -b` 做全量类型检查，通过后 `vite build` 输出到 `dist/` | 上线前、想确认类型有没有错 |
| `pnpm preview` | 用本地静态服务器预览 `dist/` 的构建产物 | 验证打包结果 |
| `pnpm lint` | 依次跑 ESLint → Stylelint → Prettier 检查，任一失败就非零退出 | 提交前自查 |
| `pnpm lint:fix` | 同上，但加 `--fix` / `--write` 自动修能修的问题 | 批量整理代码 |
| `pnpm prepare` | 安装 husky 的 git 钩子（通常由 `pnpm install` 自动触发） | 换电脑/重新 clone 后 |

几个容易忽略的点：

1. **`build` 里的 `vue-tsc -b` 不是可选项**。Vite 打包时只做转译、不做类型检查，类型错误会被静默放过；`vue-tsc -b` 才是真正的类型守门员。
2. **`lint` 是三条命令用 `&&` 串起来的**，ESLint 挂了后面的 Stylelint/Prettier 就不会跑。排查时要看第一条报错。
3. 本地项目**没有** `format` 脚本（课程项目有 `prettier --write src/`）。本地把格式化收进了 `lint:fix`。
4. 本地项目**没有**单元测试脚本（课程项目有 `test:unit` 用 Vitest），所以 `package.json` 里也没有 vitest 相关依赖。

## 七、课程前端 vs 本地前端：先记住这几条差异

迁移时 90% 的「怎么和视频里不一样」都来自这张表：

| 对比项 | 课程前端 | 本地前端 | 影响 |
| --- | --- | --- | --- |
| 包管理器 | yarn（`yarn.lock`） | pnpm（`pnpm-lock.yaml`） | 安装命令不同，不要混用 |
| Vite | 5.x | 8.x | 配置写法基本一致，Node 要求更高 |
| Vue | 3.4.x | 3.5.x | 兼容 |
| Vue Router | 4.x | 5.x | 本文用到的 API 没变 |
| Pinia | 2.x | 4.x | setup store 写法一致 |
| TypeScript | 5.4 | 6.0 | 默认更严格（strict 默认开启） |
| Tailwind | 3.4 + `tailwind.config.js` + PostCSS | 4.3 + `@tailwindcss/vite` | **入口 CSS 写法完全不同**，详见 02 篇 |
| ESLint | 8.x + `.eslintrc.cjs` | 10.x + `eslint.config.js`（flat） | 配置文件格式不同 |
| Stylelint | 无 | 有 | 新增一层样式检查 |
| husky / lint-staged / commitlint | 无 | 有 | 提交时会自动校验 |
| 样式入口 | `src/assets/styles/main.css`（v3 写法） | `src/style.css`（v4 写法） | **迁移时必须替换引入** |
| 单元测试 | Vitest | 无 | 本地不跑测试 |
