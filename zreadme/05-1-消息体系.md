# 05-1 消息体系

> 返回总览：[05-LangChain核心组件详解.md](./05-LangChain核心组件详解.md)｜下一节：[05-2-Prompt组件.md](./05-2-Prompt组件.md)
> 本节重点：LangChain 的消息类是什么，以及它在手写 openai SDK 里对应哪个 `role` 字符串。

## 一、LangChain 的消息类型

ChatModel 的输入输出都是消息列表：

| 类 | `type` | 角色 | 用途 |
| --- | --- | --- | --- |
| `SystemMessage` | `"system"` | 系统 | 人设、规则、当前时间 |
| `HumanMessage` | `"human"` | 用户 | 本轮提问 |
| `AIMessage` | `"ai"` | 助手 | 模型回复；多轮时要回填 |
| `ToolMessage` | `"tool"` | 工具 | 工具调用结果（本章不涉及） |

Prompt 模板里常用元组简写，LangChain 会自动转成对应消息类：`("system", "...")`、`("human", "{query}")`、`("ai", "...")`。

`AIMessage` 的结构如下（`type`、`content`、`response_metadata` 是最常打交道的三个属性）：

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `content` | `str` | 正文，最常取 |
| `type` | `str` | 固定 `"ai"` |
| `response_metadata` | `dict` | 厂商原始元数据：`model_name`、`finish_reason`、`token_usage`（各厂商不同） |
| `usage_metadata` | `dict \| None` | 统一 token 用量：`input_tokens`/`output_tokens`/`total_tokens`；新版 core 才有，部分兼容接口为 `None` |
| `id` / `tool_calls` | `str` / `list` | 消息 id、工具调用请求（本章不涉及） |

`AIMessage` 不适合直接返回前端：结构不 JSON 友好且带元数据。业务通常只要 `content`——这正是 OutputParser 的职责（见 [05-4-OutputParser.md](./05-4-OutputParser.md)）。

## 二、不用 LangChain 时：消息就是 `list[dict]`

手写 openai SDK 时没有消息类，所谓“消息”就是一个普通字典，`role` 是字符串常量：

```python
import os

from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_API_BASE"),
)

# 所谓“消息列表”：一个普通 list，元素是 dict
messages = [
    {"role": "system", "content": "你是一个乐于助人的助手"},
    {"role": "user", "content": "我叫慕小课"},
    {"role": "assistant", "content": "你好，我是ChatGPT，有什么可以帮到您"},
    {"role": "user", "content": "请讲一个关于程序员的冷笑话"},
]

resp = client.chat.completions.create(model="deepseek-flash", messages=messages)
print(resp.choices[0].message.content)
```

同样的四条消息，LangChain 写法：

```python
from langchain_core.messages import AIMessage, HumanMessage, SystemMessage

messages = [
    SystemMessage("你是一个乐于助人的助手"),
    HumanMessage("我叫慕小课"),
    AIMessage("你好，我是ChatGPT，有什么可以帮到您"),
    HumanMessage("请讲一个关于程序员的冷笑话"),
]
```

逐项对照：

| 用途 | LangChain | 手写 openai SDK |
| --- | --- | --- |
| 系统消息 | `SystemMessage` / `("system", ...)` | `{"role": "system", "content": ...}` |
| 用户消息 | `HumanMessage` / `("human", ...)` | `{"role": "user", "content": ...}` |
| 助手消息 | `AIMessage` / `("ai", ...)` | `{"role": "assistant", "content": ...}` |
| 工具结果 | `ToolMessage` | `{"role": "tool", "tool_call_id": ...}` |
| 模型回复 | `AIMessage`：`.content` / `.response_metadata` / `.usage_metadata` | `resp.choices[0].message.content`，元数据在 `resp.usage`、`resp.model` |
| 角色写错 | 用类或元组，`role` 由框架转换 | 字符串手写，拼错不报错，只能靠模型容错 |

两点需要记住：

1. LangChain 内部的 `type` 是 `human` / `ai`，而 OpenAI 协议里是 `user` / `assistant`，这层转换由 `ChatOpenAI` 负责。手写时要自己记住每家的命名差异（例如 Gemini 的模型消息叫 `model`）。
2. 手写版多轮对话必须自己把上一轮问答 `append` 回列表，`AIMessage` 只是把这件事实体化成对象，**并不会自动帮你存历史**（见 [05-3-Model组件.md](./05-3-Model组件.md)）。
