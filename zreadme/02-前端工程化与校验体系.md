> 本篇讲「工具为什么这么配」：Vite、TypeScript、Tailwind v4、ESLint、Stylelint、Prettier、husky，以及 pnpm 12 的两个坑。

## 一、三道关卡各管什么

写代码时 TypeScript 管类型；保存/手动执行时 ESLint、Stylelint、Prettier 管质量与格式；`git commit` 时 husky、lint-staged、commitlint 管提交。

| 工具 | 管什么 | 不管什么 |
| --- | --- | --- |
| TypeScript | 类型、变量是否存在、是否可能为 null | 缩进、引号、分号 |
| ESLint | 代码质量（未使用变量、Vue/TS 规则） | 样式、格式 |
| Stylelint | CSS / `<style>` 写法规范 | JS、格式 |
| Prettier | 纯格式（缩进、引号、换行） | 代码对错 |
| commitlint | 提交信息格式 | 代码本身 |

## 二、Vite 配置

```ts
// vite.config.ts
import { fileURLToPath, URL } from 'node:url'
import tailwindcss from '@tailwindcss/vite'
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue(), tailwindcss()],
  resolve: {
    alias: {
      // 用 @ 代表 src 目录，导入时就不需要写 ../../ 这类相对路径
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
})
```

| 配置 | 作用 | 少了会怎样 |
| --- | --- | --- |
| `vue()` | 解析 `.vue` 单文件组件 | Vite 不认识 `.vue`，直接报解析错误 |
| `tailwindcss()` | Tailwind v4 的 Vite 插件 | `@import 'tailwindcss'` 没人处理，工具类不生成 |
| `alias['@']` | `@/utils/request` → `src/utils/request` | 层级深了要写 `../../../`，移动文件全要改 |

两个关键点：

1. **别名要配两处**：Vite 解决「打包器怎么找文件」，`tsconfig.app.json` 的 `paths` 解决「编辑器/类型检查怎么找文件」。只配 Vite，编辑器会飘红「找不到模块」。
2. **端口没有显式配置**：`vite.config.ts` 没有 `server` 字段，所以用 Vite 默认 `5173`；被占用时自动换 `5174`……（`strictPort` 默认 false）。要固定就写 `server: { port: 5173, strictPort: true }`。

**为什么没有 `postcss.config.js`**：v4 把 Tailwind 变成 Vite 插件，不再走 PostCSS，也不需要 `autoprefixer`（内部用 Lightning CSS）。课程里的 `postcss.config.js` 和 `tailwind.config.js` 都不要照搬。

## 三、TypeScript 配置

### 1. 三份配置的分工

```text
tsconfig.json          根配置：files: []，只用 references 串起下面两个
├── tsconfig.app.json  浏览器业务代码（src/**/*.ts、*.tsx、*.vue）
└── tsconfig.node.json Node 环境代码（vite.config.ts）
```

```json
// tsconfig.json
{
  "files": [],
  "references": [{ "path": "./tsconfig.app.json" }, { "path": "./tsconfig.node.json" }]
}
```

`pnpm build` 里的 `vue-tsc -b` 就是构建这些被引用的子项目。拆两份是为了隔离环境：`src` 能用 `document` 但不能用 `process`；`vite.config.ts` 能用 `node:fs` 但没有 DOM。

### 2. `tsconfig.app.json` 逐项

```json
{
  "extends": "@vue/tsconfig/tsconfig.dom.json",
  "compilerOptions": {
    "types": ["vite/client"],
    "allowArbitraryExtensions": true,
    "paths": { "@/*": ["./src/*"] },
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "erasableSyntaxOnly": true,
    "noFallthroughCasesInSwitch": true
  },
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue"]
}
```

| 配置 | 含义 / 不写会怎样 |
| --- | --- |
| `extends: "@vue/tsconfig/tsconfig.dom.json"` | 继承 DOM 环境、`moduleResolution: bundler`、`jsx` 等；**`strict` 与 `verbatimModuleSyntax` 也在这里被继承为 true** |
| `types: ["vite/client"]` | 提供 `import.meta.env`；不写会报 `Property 'env' does not exist on type 'ImportMeta'` |
| `allowArbitraryExtensions` | 允许导入非 TS 扩展名文件（配合声明文件） |
| `paths` | 让 TS 认识 `@` 别名；不写则编辑器报「找不到模块」 |
| `noUnusedLocals` | 禁止未使用的局部变量/导入，报 TS6133 |
| `noUnusedParameters` | 禁止未使用的函数参数，报 TS6133 |
| `erasableSyntaxOnly` | 只允许可被擦除的 TS 语法，禁 `enum`、`namespace`、参数属性 |
| `noFallthroughCasesInSwitch` | `switch` 的 case 不允许漏写 `break` |
| `include` | 少写 `*.vue` 就不会检查组件 |

#### `strict`：真实报错

```ts
function update(params) {        // 隐式 any
  Object.assign(account.value, params)
}
// TS7006: Parameter 'params' implicitly has an 'any' type.
```

所以 `src/stores/account.ts` 写成 `function update(params: any)`——显式标注，类型检查通过。另一个常见错误是空值：

```ts
const el = ref<HTMLDivElement | null>(null)
el.value.scrollTo(0, 0)
// TS18047: 'el.value' is possibly 'null'.
```

#### `noUnusedLocals` / `noUnusedParameters`

```ts
import { ref } from 'vue'   // 没用到
// TS6133: 'ref' is declared but its value is never read.
```

课程路由守卫是 `(to, from) => {}`，`from` 没用到，在本地会报错，所以本地改成了 `(to) => {}`。确实要保留的参数可以写成 `_from`，下划线开头不检查。

#### `verbatimModuleSyntax`：为什么写 `import { type X }`

```ts
// src/models/app.ts
import { type BaseResponse } from '@/models/base'
```

`BaseResponse` 只是类型，运行时不存在。不加 `type` 会报 TS1484；即使绕过，运行时会报：

```text
The requested module '/src/models/base.ts' does not provide an export named 'BaseResponse'
```

两种合法写法：`import { type BaseResponse } from '...'` 或 `import type { BaseResponse } from '...'`。

#### `erasableSyntaxOnly`

```ts
enum Role { Human, AI }
// This syntax is not allowed when 'erasableSyntaxOnly' is enabled.
```

替代：`const ROLE = { HUMAN: 'human', AI: 'ai' } as const` + 联合类型。原因：Vite/Node 的类型剥离只删除类型，不做真正编译。

### 3. `tsconfig.node.json`

```json
{
  "compilerOptions": {
    "target": "es2023",
    "lib": ["ES2023"],
    "types": ["node"],
    "module": "nodenext",
    "noEmit": true
  },
  "include": ["vite.config.ts"]
}
```

- `types: ["node"]`：只有这份配置能用 `process`、`__dirname`。
- `lib: ["ES2023"]`：**没有 DOM**，防止在配置文件里误用浏览器 API。
- `module: "nodenext"`：项目是 `"type": "module"`，按 Node ESM 规则解析。
- 同样开启 `noUnusedLocals` / `noUnusedParameters` / `erasableSyntaxOnly`。

## 四、Tailwind CSS v4 vs 课程 v3（重点）

### 1. 入口写法

课程 `src/assets/styles/main.css`（v3）：

```css
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer base {
  .scrollbar-w-none {
    scrollbar-width: none;
  }
}
```

本地 `src/style.css`（v4）：

```css
@import 'tailwindcss';

/* v4 用 CSS 变量做主题配置 */
@theme {
  --color-brand: #646cff;
}

/* v4 用 @utility 自定义工具类 */
@utility scrollbar-w-none {
  scrollbar-width: none;
}

body {
  margin: 0;
}
```

| 对比项 | v3（课程） | v4（本地） |
| --- | --- | --- |
| 引入 | `@tailwind base/components/utilities` | `@import 'tailwindcss'` |
| 配置文件 | `tailwind.config.js` | 不需要，写进 CSS |
| 构建 | PostCSS + `postcss.config.js` | `@tailwindcss/vite` 插件 |
| 主题 | `theme.extend.colors.brand` | `@theme { --color-brand }` |
| 自定义工具类 | `@layer utilities` | `@utility` |
| 自动前缀 | `autoprefixer` | 内置 |
| 内容扫描 | `content: [...]` | 自动扫描（可用 `@source` 补充） |

### 2. `@theme` 生成类名

`--color-brand: #646cff;` 会自动派生 `text-brand`、`bg-brand`、`border-brand` 等工具类，不用再改配置文件。

### 3. `@utility` 与 `@layer`

`@utility scrollbar-w-none` 定义的是「真正的 Tailwind 工具类」：能被扫描、排序、配合变体（`md:scrollbar-w-none`）。课程用 `@layer base { .scrollbar-w-none }` 只是普通 CSS 类；v4 里自定义工具类统一用 `@utility`。

### 4. 为什么拷课程 `main.css` 会让工具类全失效

现象：页面无样式，`h-16`、`px-4`、`flex`、`bg-gray-100` 全部无效。

原因链：

1. v4 必须先 `@import 'tailwindcss'` 才会生成工具类；
2. 课程的 `@tailwind base;` 等指令 v4 不认识，不会生成任何 utility；
3. 如果 `main.ts` 改成 `import '@/assets/styles/main.css'`，那 `style.css` 根本没被引入，连 `@theme`、`@utility` 也没了。

正确动作只有一条：**`src/main.ts` 保持 `import './style.css'`**，把课程里确实需要的全局样式手动搬进 `style.css`。另外 `@import` 必须在文件最前面，否则会被 CSS 规范忽略。

## 五、ESLint 10 flat config

```js
// eslint.config.js
import js from '@eslint/js'
import skipFormatting from '@vue/eslint-config-prettier/skip-formatting'
import { defineConfigWithVueTs, vueTsConfigs } from '@vue/eslint-config-typescript'
import pluginVue from 'eslint-plugin-vue'

export default defineConfigWithVueTs(
  { name: 'app/files-to-lint', files: ['**/*.{ts,mts,tsx,vue}'] },
  {
    name: 'app/files-to-ignore',
    ignores: ['**/dist/**', '**/dist-ssr/**', '**/coverage/**', '**/node_modules/**'],
  },
  js.configs.recommended,
  pluginVue.configs['flat/essential'], // Vue 基础规则
  vueTsConfigs.recommended, // TS 规则 + .vue 支持
  {
    name: 'app/rules',
    rules: {
      // 允许显式 any（跟随课程示例，后续可收紧）
      '@typescript-eslint/no-explicit-any': 'off',
    },
  },
  skipFormatting, // 关闭与 Prettier 冲突的格式规则
)
```

| 片段 | 作用 |
| --- | --- |
| `defineConfigWithVueTs(...)` | 组合 flat config 数组，让 Vue SFC 与 TS 解析器配合 |
| `files` | 只检查 ts/mts/tsx/vue |
| 只含 `ignores` 的对象 | **全局忽略**；写在其他对象里的 ignores 只对该对象生效 |
| `js.configs.recommended` | ESLint 官方推荐规则 |
| `flat/essential` | Vue 3 必备规则 |
| `vueTsConfigs.recommended` | TS 解析器 + 推荐规则，能解析 `<script lang="ts">` |
| `app/rules` | 后写覆盖先写 |
| `skipFormatting` | 避免 ESLint 与 Prettier 互相打架 |

### 显式 any vs 隐式 any

```ts
const messages = ref<any[]>([])  // 显式：你亲手写了 any
function update(params: any) {}   // 显式
function update(params) {}        // 隐式：没写类型，TS 推不出来
```

| 类型 | 谁在管 | 本项目 |
| --- | --- | --- |
| 显式 any | ESLint `no-explicit-any` | 已 `off`，允许 |
| 隐式 any | TypeScript `noImplicitAny`（`strict` 开启） | 报 TS7006，必须补类型 |

关掉 ESLint 的规则**不等于**可以随便不写类型；隐式 any 是类型系统层面的事，ESLint 管不到。

## 六、Stylelint

```js
// stylelint.config.js
export default {
  extends: ['stylelint-config-standard', 'stylelint-config-recommended-vue'],
  ignoreFiles: ['**/dist/**', '**/node_modules/**'],
  rules: {
    'no-empty-source': null, // 允许空 <style>（课程示例大量保留）
    'import-notation': 'string', // 支持 @import 'tailwindcss'
    'at-rule-no-unknown': [
      true,
      {
        ignoreAtRules: ['theme', 'utility', 'variant', 'custom-variant', 'apply', 'plugin', 'source', 'reference'],
      },
    ],
  },
}
```

| 配置 | 含义 |
| --- | --- |
| `stylelint-config-standard` | 官方标准规则（属性顺序、颜色写法等） |
| `stylelint-config-recommended-vue` | 解析 `.vue` 的 `<style>` 块（依赖 `postcss-html`） |
| `no-empty-source: null` | 关掉「空样式源」报错 |
| `import-notation: 'string'` | 允许 `@import 'x'`，而不是只允许 `url('x')` |
| `at-rule-no-unknown` + 白名单 | 放行 `@theme`、`@utility`、`@apply` 等 Tailwind 指令 |

**为什么关 `no-empty-source`**：课程组件大量写成 `<style scoped></style>`。默认规则会报 `Unexpected empty source`，`pnpm lint` 失败 → pre-commit 失败 → **提交被阻断**。

**为什么 `import-notation: 'string'`**：标准规则默认要求 `@import url(...)`，而 v4 官方写法是 `@import 'tailwindcss'`，不改就报错。

检查范围是 `stylelint "src/**/*.{vue,css}"`，即 `src` 下所有 `.vue` 的 `<style>` 和所有 `.css`。

## 七、Prettier

```json
{
  "semi": false,
  "singleQuote": true,
  "printWidth": 100,
  "trailingComma": "all"
}
```

| 配置 | 含义 |
| --- | --- |
| `semi: false` | 行尾不加分号 |
| `singleQuote: true` | 字符串优先单引号 |
| `printWidth: 100` | 超过 100 字符换行 |
| `trailingComma: "all"` | 多行结构最后一项也加逗号，diff 更干净 |

`.prettierignore` 跳过 `node_modules`、`dist`、`dist-ssr`、`coverage`、`pnpm-lock.yaml`（锁文件由 pnpm 维护）。

分工：**ESLint 管质量、Stylelint 管样式质量、Prettier 管格式**。`pnpm lint` 的三段就是 `eslint . && stylelint ... && prettier --check src/`；`lint:fix` 则加 `--fix` / `--write`。

## 八、提交校验链路

```text
git commit -m "feat: xxx"
  ▼
.husky/pre-commit: pnpm exec lint-staged
   *.{js,ts,vue}       → eslint --fix → prettier --write
   *.{css,vue}         → stylelint --fix → prettier --write
   *.{json,md,yml,yaml} → prettier --write
   修复后自动重新 git add；任一失败 → 提交中止
  ▼
.husky/commit-msg: pnpm exec commitlint --edit "$1"
   校验 type(scope): subject；不合法 → 提交中止
  ▼
写入提交
```

`package.json` 里的 `lint-staged`：

```json
{
  "lint-staged": {
    "*.{js,ts,vue}": ["eslint --fix", "prettier --write"],
    "*.{css,vue}": ["stylelint --fix", "prettier --write"],
    "*.{json,md,yml,yaml}": ["prettier --write"]
  }
}
```

- 按 glob 分派；`.vue` 同时命中前两组，所以 Prettier 会跑两次，正常。
- 命令后不用写文件名，lint-staged 自动拼接暂存文件的路径。
- `--fix` 的改动会被自动重新 add，进入本次提交。
- 只检查暂存区，没 `add` 的改动不参与。

`commitlint.config.js` 继承 `@commitlint/config-conventional`，合法示例：

```bash
git commit -m "feat(home): 新增计数器示例"
git commit -m "fix: 修正锁文件版本"
```

`type` 常用：`feat` / `fix` / `docs` / `style` / `refactor` / `test` / `chore`。

## 九、pnpm 12 的两个真实坑

### 坑 1：`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`

**现象**：

```text
ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION
Cannot install prettier@3.10.1: it was published less than the minimum release age
```

**原因**：pnpm 12 默认启用供应链安全策略，发布太新的包不允许装，防止投毒包被立即安装。`^3.10.1` 解析到的新版本可能「太新」。

**解决 A（本项目采用）**——在 `pnpm-workspace.yaml` 豁免：

```yaml
minimumReleaseAgeExclude:
  - prettier@3.10.1
```

**解决 B**——重建锁文件，退回满足年龄策略的版本：

```bash
pnpm clean --lockfile
pnpm install
```

注意 B 会改变依赖版本，装完要重新 `pnpm build` 验证。不建议直接把 `minimumReleaseAge` 关闭。

### 坑 2：`ERR_PNPM_UNEXPECTED_STORE`

**现象**：`node_modules` 存在，但安装/启动时报：

```text
ERR_PNPM_UNEXPECTED_STORE
node_modules was installed by a different store
```

**原因**：pnpm 的 `node_modules` 是指向全局 store 的链接。项目若在另一个环境（沙箱、另一个终端、另一个盘）装过依赖，可能生成了**项目级 store**；换到正常终端后，store 路径不同，pnpm 拒绝继续。

**解决**——在正常终端执行：

```bash
pnpm install          # 重新链接
pnpm install --force  # 仍报错时强制重装
```

可用 `pnpm store path` 确认 store 位置。**不要手动删 `node_modules`**：问题本质是 store 归属不一致，删目录不解决，Windows 下还可能误删 junction 目标。确需清理时用 `pnpm clean`。

## 十、`.editorconfig` 与 `.gitignore`

```ini
# .editorconfig
root = true

[*]
charset = utf-8
indent_style = space
indent_size = 2
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

- 统一 UTF-8、2 空格、LF、文件末尾空行，避免「编辑器 4 空格 / Prettier 2 空格」来回改。
- `[*.md]` 不清行尾空格：Markdown 里两个空格是换行语法。
- `.gitignore` 忽略 `node_modules`、`dist`、`*.local`、`.idea`、`.DS_Store`；`.vscode/*` 但保留 `extensions.json`，只共享推荐插件。
